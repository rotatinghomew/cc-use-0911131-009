# 经营分析样例

samples 是抽样复核明细，sample_id 的 revision 表示复核更正，inclusion_probability 为该层入样概率，review_complete 为是否完成。operator_id、site_id、version 标识重复操作者、站点与辅助版本。sampling_frame 给出每周各 stratum 总体量，reference_start、reference_end 与 reference_version 描述参考期。

日期采用 ISO 8601；样例完全由固定种子生成，不含真实个人、机构或设备资料。字段缺省与数值零的含义不同。原有 fixtures/demo.json 仍用于既有业务流程。

## monitoring 的读法

- `estimate` 是按 `1 / inclusion_probability` 加权的总体比例；`unweighted_estimate` 只是同一周明细里的原始比例，用于解释“比例为什么看起来变了”，不能当作总体估计。
- `interval` 是按抽样层分层、按 operator 聚类的线性化区间。同一 operator 出现的多条记录不会当作多条独立证据。
- 同一 `sample_id` 有多条 revision 时只取 as_of 当日已知的最高 revision。修订替代旧结论，重放不重复累计。
- `review_complete=false` 不计入采纳率、修改率的分母；它进入 `coverage_rate`（分子是完成复核的行数，分母是 sampling_frame 的总体量）。未完成不等于“未采纳”。
- `status`：`ok` 表示可估且已给出区间；`insufficient_evidence` 表示点估计仍给出但证据不足，`interval` 为 null；`unestimable` 表示该层没有总体框或入样概率非法，`estimate` 为 null，不填零、也不换成未加权结果。`reason` 给出具体原因。
- `baseline_scope`：`version` 表示与参考期内同一版本的基线比较；`pooled` 表示参考期没有该版本，退回参考期合计基线（该周不应被读成模型退化）。
- `design_checks` 是抽样结构诊断；`status=fail` 会阻断该周总体估计，`warn` 表示抽样结构发生了变化。

## sampling_shift_only.json

这份样例从 2026-03-19 起把抽样比例从 routine/modified = 40/40 改为 10/70，但底层复核行为（同一批 operator、同一接受倾向）完全不变。原始比例会明显下降；设计加权估计不会。若监测把它报成质量下降，就是抽样变化与质量变化没有分开。
